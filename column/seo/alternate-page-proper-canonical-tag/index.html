代替ページ（適切なcanonicalタグあり）
の意味と対処

2026年11月25日 Search Consolecanonicalインデックス登録

この記事でわかること

  • 「代替ページ（適切な canonical タグあり）」が出ているときに、Googleの中で起きていること
  • 放っておいてよいケースと、確認したほうがよい3つのケースの見分け方
  • URLのパターンで仕分けし、URL検査ツールで正規URLを確かめる手順
  • 原因別の直し方と、「検証」が失敗するときの考え方

Search Consoleの「ページのインデックス登録」を開くと、「代替ページ（適切な canonical タグあり）」という理由で、数十〜数百のURLが「登録されていません」に入っていることがあります。数が多いと「サイトに何か問題があるのでは」「修正して検証を押すべきか」と不安になりますが、多くの場合、これはエラーではありません。この記事では、このステータスの意味と、本当に手を入れるべきケースの見分け方を、Googleの公式ヘルプに沿って整理します。

結論：「代替ページ（適切な canonical タグあり）」は、そのURLが別の正規ページの代わりとして扱われ、正規ページの方が正しく登録されている状態で、Googleは通常これ以上の対処は不要としています。確認が必要なのは、一覧に「検索に出てほしいページ」が混ざっているとき、正規ページ側が登録されていないとき、件数が急に増えたときの3つだけです。URLのパターンで仕分けし、気になるURLはURL検査ツールで「Googleが選択した正規URL」を確かめれば、30分ほどで判断できます。エラーではないので、「修正を検証」を押す必要はありません。

「代替ページ（適切な canonical タグあり）」とは

同じ内容、またはほぼ同じ内容のページが複数のURLで見られる場合、Googleはその中から1つを「正規ページ」として選び、検索結果には正規ページだけを出します。ほかのURLは「重複ページ」や「代替ページ」として扱われ、インデックスには登録されません。

Search Consoleのヘルプでは、「代替ページ（適切な canonical タグあり）」を、別のページの代替（PC版の正規ページに対するAMPページやモバイル版など）としてマークされたページで、正規ページへのリンクが正しく指定されているため、これ以上の対処は必要ない状態と説明しています。また、ページが重複や代替としてマークされるのは、Googleが正規ページを検出して登録したことを表しているので、通常は問題ないとも書かれています（出典：ページ インデックス登録レポート｜Search Console ヘルプ）。

実務では、AMPやモバイル版に限らず、広告や計測のパラメータが付いたURL、末尾のスラッシュの有無、「index.html」付きのURLなど、canonicalタグで正規URLを指しているページがこの理由に入ってくるのをよく見ます。いずれも「canonicalタグがきちんと働いている」ことの表れで、レポートの「登録されていません」という言葉ほど深刻な状態ではありません。

ポイント：Googleは、サイトのすべてのURLがインデックスに登録されるわけではなく、登録されるのは正規ページのみだと説明しています（出典：ページ インデックス登録レポート｜Search Console ヘルプ）。「登録されていないURLの数を0にする」ことを目標にする必要はありません。

似たステータスとの違い

同じ「重複・正規」の系統に、似た名前のステータスがいくつかあります。対処が要るかどうかが違うので、どれが出ているかを最初に確かめてください。

ステータス状態対処の要否
代替ページ（適切な canonical タグあり）canonicalタグで正規ページを指しており、Googleもそれに従っている通常は不要
重複していますが、ユーザーが正規ページとして選択していませんcanonicalの指定が無いまま、Googleが別のURLを正規ページに選んだ選ばれた正規URLが意図どおりなら不要。違えばcanonicalを明示する
重複しています。Google により、ユーザーがマークしたページとは異なるページが正規ページとして選択されましたcanonicalで指定したURLとは別のURLを、Googleが正規ページに選んだ確認が必要。指定と実態がずれている

ヘルプでは、2つ目の「ユーザーが正規ページとして選択していません」について、エラーではなく意図したとおりに機能しているとしたうえで、Googleが誤ったURLを正規URLに選んでいると思われる場合は正規URLを明示できる、と説明しています（出典：ページ インデックス登録レポート｜Search Console ヘルプ）。手を入れる優先度が高いのは3つ目で、「代替ページ」は最も優先度の低いステータスです。

確認したほうがよい3つのケース

通常は対処不要とはいえ、canonicalタグの設定ミスがあると、検索に出てほしいページまで「代替ページ」に入ってしまいます。次の3つに当てはまるときだけ、中身を確認してください。

1. 一覧に「検索に出てほしいページ」が混ざっている

パラメータ付きのURLだけでなく、記事ページ、商品ページ、カテゴリページ、ページ送りの2ページ目以降など、それ自体で検索に出てほしいページが並んでいる場合です。テンプレートの設定で、すべてのページのcanonicalがトップページや1ページ目を指しているといったミスがあると、Googleはその指定に従ってしまいます。

2. canonicalで指した先のページが登録されていない

代替ページそのものは問題なくても、指している正規ページ側が「登録されていません」に入っていると、そのページはどちらのURLでも検索に出ません。正規ページ側の状態は、次の章の手順でURL検査ツールを使って確かめます。

3. 件数が急に増えた

サイトのリニューアル、CMSやテーマの変更、広告のパラメータ付きURLの配布、ECサイトの絞り込み機能の追加などのあとに、件数が急に増えることがあります。多くはパラメータ付きURLが新しく見つかっただけですが、テンプレート変更でcanonicalの出力が変わった可能性もあるので、増えた時期と作業の時期を突き合わせてください。

自分で確かめる手順

件数が数百あっても、1件ずつ見る必要はありません。URLの形で仕分けると、確認すべきURLはごく一部に絞れます。

確認手順（上から順に）

  • 1. Search Consoleの「ページ」レポートで「代替ページ（適切な canonical タグあり）」を開き、例として表示されるURLの一覧をエクスポートする
  • 2. スプレッドシートで、URLを「?より後ろにパラメータがある」「末尾のスラッシュやindex.htmlの違い」「httpやwwwの違い」「それ以外」に分ける
  • 3. 「それ以外」に入ったURLを開き、それが検索に出てほしいページかどうかを判断する。出てほしくないもの（印刷用ページ、並べ替え結果など）は確認を終える
  • 4. 検索に出てほしいページがあれば、URL検査ツールに入れ、「ユーザー指定の正規URL」と「Google が選択した正規URL」を確かめる
  • 5. ページのソースを開き、canonicalタグが自分自身ではなく別のURLを指していないかを見る。テンプレート共通の設定なら、同じテンプレートのほかのページも1〜2件確かめる
  • 6. canonicalで指している先のURLもURL検査ツールに入れ、「URL は Google に登録されています」と出るかを確かめる

Googleは、正規化の問題を調べるときは、まずURL検査ツールでGoogleがどのページを正規ページとみなしているかを確かめ、指定した正規URLよりGoogleが選んだURLの方が検索ユーザーにとって理にかなっていないかを考えるよう勧めています（出典：正規化に関する問題の修正｜Google 検索セントラル）。手順4と6はこの考え方に沿ったものです。

注意：手順2で「パラメータ付き」や「表記ゆれ」に入ったURLは、正規ページ側が登録されていれば確認不要です。ここで時間を使うより、「それ以外」に入ったURLを丁寧に見てください。

よくあるURLのパターンと直し方

当社がサイトの点検で見ることの多いパターンと、それぞれの対応をまとめます。上の2つは対処不要、下の3つは直すべきケースです。

代替ページに入っているURL状態対応
広告・メール・SNSの計測用パラメータが付いたURLcanonicalで本来のURLを指している。正常対処不要。サイト内リンクにはパラメータ付きURLを使わない
末尾のスラッシュ有無、index.html付き、http・wwwの違いcanonicalで正規の表記を指している。正常対処不要。できればリダイレクトで1つの表記にそろえる
記事・商品などの個別ページテンプレートのcanonicalが別のページ（トップや一覧）を指している各ページのcanonicalが自分自身のURLを指すように直す
一覧のページ送り（2ページ目以降）すべて1ページ目をcanonicalにしている2ページ目以降に固有の商品や記事が載っているなら、各ページを自分自身のcanonicalにする
内容が別物のページ似たテンプレートのページを、内容が違うのに同じ正規URLにまとめているcanonicalを自分自身に戻し、ページごとの違いを本文で明確にする

正規URLを伝える方法について、Googleは効果の強い順に、リダイレクト、rel="canonical"、サイトマップへの掲載を挙げ、複数を組み合わせると希望する正規URLが表示されやすくなるとしています（出典：rel="canonical" などを利用して正規ページを指定する方法｜Google 検索セントラル）。canonicalタグを直したら、サイトマップに載せるURLと、サイト内リンクで使うURLも正規URLにそろえてください。指定がばらばらだと、Googleが別のURLを選ぶ理由になります。

直したあとは、正規ページにしたいURLをURL検査ツールで確認し、必要なら再クロールをリクエストします。Googleは、コンテンツの問題を直したあとも、ページが重複のまとまりに最長2週間ほど残ることがあると説明しています（出典：正規化に関する問題の修正｜Google 検索セントラル）。

「検証」が失敗するときの考え方

「代替ページ」の行で「修正を検証」を押したところ、「不合格」になったという相談はよくあります。ShopifyのコミュニティでもSearch Consoleでこの理由の検証が失敗するという質問が寄せられています（参考：代替ページ(適切な canonical タグあり)で検証が失敗になっている｜Shopify Community）。

検証は、問題のあるURLがすべて解消されたかをGoogleが確かめる仕組みです。代替ページはエラーではなく、canonicalタグを使っている限りURLはこの理由に残り続けるので、検証が通らないのは自然なことです。Search Consoleのヘルプも、問題によっては修正して検証することに常に意味があるとは限らず、検証をリクエストしなくても、Googleはクロールのたびに件数を更新すると説明しています（出典：ページ インデックス登録レポート｜Search Console ヘルプ）。

代替ページについては、検証を押さずに、前の章の手順で「検索に出てほしいページが混ざっていないか」だけを確かめれば十分です。検証の結果は、サイトの評価や順位には関係しません。

それでも解決しないときの判断の目安

canonicalを直しても状況が変わらないときは、次の目安で判断してください。期間は当社が実務で見ている目安で、Googleが保証するものではありません。

状況判断
canonicalを直してから2〜3週間以内待つ。再クロールのリクエストは重要なページに1回で十分
1か月以上たっても、Googleが別のURLを正規ページに選び続ける2つのページの中身が似すぎていないかを見直す。Googleは、まとめられたページ同士が十分に違うことが重要だとしている（出典：正規化に関する問題の修正｜Google 検索セントラル）
正規ページ側が「クロール済み - インデックス未登録」などで登録されないcanonicalではなく、ページの評価の問題として扱う。内容の独自性や内部リンクを見直す
件数が増え続け、どのテンプレートが原因か分からないCMS・テーマ・アプリの設定を、件数が増えた時期の変更履歴と照らし合わせる。制作会社やCMSの提供元に、canonicalの出力ルールを確認する

代替ページの件数そのものを減らしたい場合は、サイト内リンク、サイトマップ、広告のリンク先に、パラメータ付きや表記ゆれのURLが使われていないかを見直します。ただし件数が減っても検索の成果には直接関係しないので、優先度は低めで構いません。

LnXの見解

Search Consoleの「登録されていません」は、言葉の印象が強いため、問題のないURLまで直そうとして時間を使ってしまうケースが少なくありません。「代替ページ（適切な canonical タグあり）」は、その代表です。当社がサイトを点検するときも、この理由は件数ではなく「中身にどんなURLが入っているか」だけを見ています。

注意したいのは、canonicalの設定ミスがテンプレート単位で起きることです。記事ページや商品ページのcanonicalが一覧ページを指していると、新しく作ったページが次々と代替ページに入り、どれだけ記事を増やしても検索に出ません。記事やページを増やす運用では、公開前のチェック項目にcanonicalの確認を入れておくと、このミスを早く見つけられます。当社では、記事テンプレートにcanonicalと構造化データ、サイトマップの自動更新を組み込み、ページが増えても設定がぶれない仕組みにしたうえで、記事制作を進めています。

※Search Consoleの画面やGoogleの仕様は更新されます。作業前に最新の公式情報も確認してください。

よくある質問

Q「代替ページ（適切な canonical タグあり）」は、放っておいても順位は下がりませんか？

このステータス自体が順位を下げることはありません。Googleは、正規ページへのリンクが正しく指定されているため対処は不要と説明しています。確認すべきなのは、検索に出てほしいページが混ざっていないか、正規ページ側が登録されているかの2点です。

Q「修正を検証」を押したら不合格になりました。どうすればよいですか？

代替ページはエラーではないため、canonicalタグを使っている限りURLは残り、検証が通らないのは自然なことです。検証の結果は順位に関係しないので、そのままで構いません。中身に問題のあるURLが無いかだけを確かめてください。

Q件数が数百件あります。減らしたほうがよいですか？

減らす必要はありません。Googleは、すべてのURLが登録されるわけではなく、登録されるのは正規ページのみだと説明しています。減らしたい場合は、サイト内リンクやサイトマップ、広告のリンク先にパラメータ付きのURLを使わないようにします。

Q記事ページが代替ページに入っていました。何を直せばよいですか？

ページのソースでcanonicalタグを確認し、記事自身のURLではなく別のURL（トップページや一覧ページなど）を指していれば、自分自身を指すように直します。テンプレート共通の設定が原因のことが多いので、同じテンプレートのほかのページも確認してください。

Q「重複しています。Google により、ユーザーがマークしたページとは異なるページが正規ページとして選択されました」との違いは何ですか？

代替ページは、canonicalで指定したとおりにGoogleが正規ページを選んでいる状態です。もう一方は、指定とは別のURLをGoogleが正規ページに選んだ状態で、こちらは指定と実態がずれているため、ページの中身や内部リンク、サイトマップの指定を見直す必要があります。
