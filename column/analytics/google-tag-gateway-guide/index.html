Googleタグゲートウェイ（GTG）とは何か

Googleタグゲートウェイ（Google Tag Gateway／GTG）は、Googleのタグを、自社が管理するウェブインフラ経由で配信する仕組みです。Google広告ヘルプでは、コンテンツ配信ネットワーク（CDN）、コンテンツマネジメントシステム（CMS）、ロードバランサなど、自社のウェブインフラを「ウェブサイトとGoogleの広告・測定サービスの間のゲートウェイ」として使う方式だと説明されています。

従来、GA4やGoogle広告のタグは googletagmanager.com という外部ドメインから読み込まれ、そこへデータを送っていました。GTGを導入すると、この読み込みと送信が自社ドメイン配下のパスを経由するようになります。訪問者のブラウザから見ると「同じサイトへの通信」に見える、という点が最大の違いです。

観点 従来の配信（外部ドメイン） タグゲートウェイ経由
タグの読み込み元 googletagmanager.com など外部ドメイン 自社ドメイン配下のパス
ブラウザからの見え方 サードパーティへの通信 自社サイトへの通信
必要なもの タグの設置のみ 対応CDN／サーバー等のインフラ設定
設定の担当 マーケ担当・代理店で完結しやすい インフラ管理者・制作会社の関与が必要
Cookieの扱い タグが直接書き込む ゲートウェイがGoogleのファーストパーティCookieのみを転送

Cookieの扱いは公式に明記されています：Google広告ヘルプによれば、GTGで使用されるのはGoogleのファーストパーティ Cookieのみで、ゲートウェイ経由で転送されたGoogle以外のファーストパーティ Cookieはすべて削除されるとされています。自社のログイン用Cookieや他社ツールのCookieがGoogleに渡る設計ではない、という点は社内説明の際に押さえておくと話が早く進みます。

そもそも、なぜ計測が失われているのか

GTGが登場した背景には、ブラウザ側でトラッキングの制限が年々強まってきたという事情があります。中小企業の現場で実際に起きているのは、次のような状態です。

1

ブラウザによるCookieの保持期間の短縮

SafariのITPをはじめ、主要ブラウザはスクリプトが書き込んだCookieの保持期間を短く制限しています。「広告をクリックした日と問い合わせた日が離れているほど、紐付けが切れやすくなる」という構図です。検討期間の長いBtoBや高単価商材ほど影響を受けます。

検討期間が長い商材ほど、計測ロスは大きくなりやすい
2

広告ブロッカー・トラッキング防止機能によるスクリプト遮断

拡張機能やブラウザ標準の保護機能が、既知の計測ドメインへのリクエストそのものを止めることがあります。この場合、タグは発火する以前に読み込まれないため、GTMのプレビューでは正常に見えていても実データが欠ける、という厄介な症状になります。

「設定は合っているのに数が合わない」原因の一つ
3

結果として、広告の判断材料が痩せる

計測ロスは「レポートの数字が少し減る」だけの問題ではありません。コンバージョンデータは、自動入札の学習に使われる燃料でもあります。取りこぼしが多いほど、媒体側の最適化は不利な条件で回ることになります。

計測精度の改善は、レポートの正確さと入札精度の両方に効く

GTGは、このうち「外部ドメインだから止められる・短縮される」というタイプの損失に対する打ち手です。逆に言えば、タグの設定ミスやトリガー条件の誤りといった設計側の欠損は、GTGを入れても一切直りません。順番としては、まず基本の計測設計を点検し、そのうえで検討するものだと考えてください。

導入方式の選択肢と、必要になる前提

GTGは「管理画面のスイッチを入れれば終わり」ではなく、自社サイトの配信インフラ側の設定が必要です。Google広告ヘルプでは、設定方法が使用するインフラごとに分かれて案内されており、代表的なものは次のとおりです。

方式 前提となる環境 実務上の目安
CDN連携型 Cloudflare・Akamai・Fastly・Amazon CloudFront などのCDNを利用している すでにCDNを通しているサイトなら比較的短時間で設定できる
ロードバランサ型 Google Cloud のロードバランサ配下でサイトを配信している インフラ担当者が社内・委託先にいることが前提
サーバーサイドGTM（sGTM）併用 サーバーサイドのタグ用コンテナを別途構築・運用する 自由度は高いが、サーバー費用と運用の手間が継続的に発生する
設定の入口 Googleタグ側／Googleタグマネージャー側のいずれからも設定できる 既存の管理方法に合わせて選ぶ

「CDNを使っていない」サイトが実は多い：共用レンタルサーバー上のWordPressで、CDNを挟んでいないサイトは中小企業では珍しくありません。この場合、GTGの導入にはまずCDNを導入するところからという話になり、必要な工数と費用の性質が変わります。検討の最初に「自社サイトはどこから配信されているか」を制作会社に確認してください。

手順の全体像

  1. 現状の配信構成を把握する——ドメイン、CDNの有無、サーバー環境、サイトの管理者は誰か
  2. いまの計測が正しいか点検する——タグの二重発火、未設置ページ、トリガー条件の誤りを先に潰す
  3. 対応方式を選ぶ——利用中のCDN／ロードバランサに合わせて、公式ヘルプの該当手順を確認する
  4. ステージング環境か低リスクな時間帯で設定する——配信経路に手を入れるため、サイト全体に影響しうる
  5. 検証する——Tag Assistant、GA4のリアルタイム、広告側のコンバージョン列を突き合わせる
  6. 切り替え前後の数値を比較する——期間を揃え、変化を記録として残す

切り替えは「サイトの配信」に触る作業です：タグの追加とは影響範囲が違います。設定を誤るとページ自体の表示に影響する可能性があるため、必ずサイトを管理している制作会社・インフラ担当と連携し、切り戻し手順を決めてから実施してください。広告の繁忙期やキャンペーン期間中の実施は避けるのが無難です。

中小企業は導入すべきか｜判断の基準

結論から言えば、全社が今すぐ入れるべきものではありません。効果の出方は広告費の規模と商材の性質に強く依存し、一方でインフラ側の作業は確実に発生します。次の観点で切り分けてください。

導入検討チェックリスト

【優先度が高くなる条件】

  • 広告費が月数十万円以上あり、コンバージョン数で入札を最適化している
  • 検討期間が長く、初回訪問から成約までに日数が空く商材である
  • 広告管理画面とGA4・CRMの数値の乖離が慢性的に大きい
  • すでにCDN（Cloudflare等）を通してサイトを配信している
  • サイトを管理している制作会社・インフラ担当と連携が取れる

【後回しでよい条件】

  • そもそもコンバージョン計測が正しく設定できていない
  • 月間のコンバージョン数が数件で、母数として判断に使えていない
  • 広告をほとんど使っておらず、自然流入が中心である
  • CDNを使っておらず、導入から始める必要がある
  • サイトの管理権限が誰にあるのか分からない状態にある

【先に手を打つべきこと】

  • GTMコンテナの棚卸し（不要タグ削除・二重計測の解消）
  • キーイベント（コンバージョン）の定義と発火条件の再確認
  • 拡張コンバージョン、コンバージョンAPIなど媒体側で完結する精度向上策
  • 受注データを媒体に戻す運用（オフラインコンバージョン）の検討

費用対効果の考え方：GTGの導入判断は、「取りこぼしている件数 × 1件あたりの粗利」と「導入・維持にかかる手間」を並べるのが実務的です。月に数件の取りこぼしなら設定作業の価値は小さく、広告費が大きく取りこぼしが数十件規模なら十分に見合います。まずは広告管理画面とGA4・CRMの数字を並べ、乖離がどれくらいあるかを測るところから始めてください。

導入前後に確認すべきこと

1. 「入れれば全部取れる」わけではない

GTGは外部ドメイン起因の損失を減らす仕組みであり、ブラウザ側の制限すべてを無効化するものではありません。また同意管理（コンセントモード）の設定が入っている場合、同意状況に応じた制御はそのまま働きます。「導入したのに数字が変わらない」という声の多くは、期待値の置き方に原因があります。

2. 数値が動いたときの説明を用意しておく

計測経路を変えると、コンバージョン数やセッション数が切り替え前後で不連続になることがあります。これは施策の成果ではなく計測条件の変化ですから、切り替え日を記録し、前後比較の際は必ず注釈を添えてください。記録がないと、数か月後に「あの月から数字が変わったが理由が分からない」という調査が発生します。

3. プライバシーポリシーと社内説明

自社ドメイン経由でデータを中継する構成になるため、「どのデータが、どこを通って、どこへ渡っているか」を説明できる状態にしておくことをお勧めします。個人情報の取り扱いに関する社内規程やプライバシーポリシーの記載と矛盾がないか、導入時に一度確認しておくと後が楽です。

4. 属人化させない

GTGはインフラ側に設定が残るため、設定した人がいなくなると誰も触れない状態になりがちです。設定内容・利用したCDN・切り替え日・切り戻し手順を、GTMのバージョンメモや社内ドキュメントとして必ず残してください。

検証の観点：切り替え後は、①タグが自社ドメイン経由で読み込まれているか（ブラウザの開発者ツールのネットワークタブ）、②GA4のリアルタイムでイベントが届いているか、③広告側の管理画面でコンバージョンが計上されているか——この3点を必ず確認してください。1つでも欠けている状態で放置すると、気付かないうちにデータが止まります。

LnXの見解

ご相談をいただくとき、「タグゲートウェイを入れたい」という形で話が来ることはほとんどありません。実際に来るのは「広告の管理画面では30件なのに、GA4では18件しか出ていない」「問い合わせ管理表と広告の数字が毎月ずれる」という相談です。そして原因を切り分けていくと、ブラウザ側の制限による損失に行き着く前に、タグの二重発火や未設置ページ、トリガー条件の誤りが見つかることのほうが圧倒的に多いのが実情です。

ですので、私たちは順番を大事にしています。まずコンテナの棚卸しと計測設計の点検、次に拡張コンバージョンやコンバージョンAPIといった媒体側で完結する精度向上策、そのうえでまだ乖離が残り、かつ広告費の規模が見合うならタグゲートウェイ——という流れです。逆にしてしまうと、インフラに手を入れたのに数字が変わらず、原因の切り分けだけが複雑になります。

もう一つ現場感としてお伝えしたいのは、この手の施策は「サイトを管理している人と連携できるか」で成否がほぼ決まるということです。CDNの管理画面に誰がアクセスできるのか、切り戻しは誰が判断するのか。ここが曖昧なまま進めると、トラブル時に動けません。LnXでは広告・LP・計測を同じ担当が見るため、切り替え前後の数値変動を広告の設定変更やサイト改修と並べて確認できます。計測は売上を作る施策ではありませんが、施策の良し悪しを判断できる唯一の土台です。ここに投資する価値があるかどうかは、いま何件取りこぼしているかを測ってから決めれば十分です。

よくある質問

Q Googleタグゲートウェイを入れると、計測できていなかった分がすべて戻りますか？

すべては戻りません。GTGは、タグが外部ドメインから配信されることに起因する損失を減らす仕組みです。ブラウザ側の制限やユーザーの同意設定に基づく制御はそのまま働きますし、タグの設定ミスやトリガー条件の誤りによる欠損はまったく別の問題です。実務上は、まず計測設計の点検で直せる分を直し、そのうえで残る乖離に対する打ち手として検討するのが適切です。

Q 導入すると、自社サイトのCookieや他社ツールのデータがGoogleに渡ってしまいませんか？

Google広告ヘルプでは、Googleタグゲートウェイで使用されるのはGoogleのファーストパーティCookieのみであり、ゲートウェイ経由で転送されたGoogle以外のファーストパーティCookieはすべて削除されると説明されています。ただし、自社の配信インフラを経由する構成に変わることは事実ですので、プライバシーポリシーの記載や社内規程と矛盾がないかは導入時に確認しておくことをお勧めします。

Q レンタルサーバーのWordPressサイトでも導入できますか？

そのままでは難しい場合があります。設定方法はCDNやロードバランサといった配信インフラごとに用意されているため、CDNを挟んでいないサイトでは、まずCDNの導入から検討することになります。この場合は工数も費用の性質も変わりますので、先に制作会社へ「現在サイトはどこから配信されているか」を確認してください。

Q 導入したあと、コンバージョン数が急に増えたり減ったりすることはありますか？

計測経路が変わるため、切り替え前後で数値が不連続になることがあります。これは施策の成果ではなく計測条件の変化です。切り替え日を必ず記録し、前後比較のレポートには注釈を添えてください。記録がないと、数か月後に数値の変化を追うときに原因の特定が難しくなります。

Q 先にやっておくべき計測の改善はありますか？

はい。GTMコンテナの棚卸し（不要タグの削除、二重計測の解消）、キーイベントの定義と発火条件の再確認、そして拡張コンバージョンやコンバージョンAPIなど媒体側で完結する精度向上策です。これらは配信インフラに手を入れずに実施でき、効果も分かりやすいため、順番としては先に着手することをお勧めします。
