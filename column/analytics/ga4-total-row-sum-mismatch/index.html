計測・GA4

GA4で行の合計と合計値が
合わない原因と確認手順

2026年11月27日 GA4計測レポート

この記事でわかること

  • GA4の「合計」の値が、下の行を足した数と一致しない理由
  • 行の合計と合計値がずれる、よくある原因6つ
  • 行の合計が「多い」か「少ない」かで原因を絞る方法
  • 10〜20分でできる確認手順と、原因別の対処・判断の目安

GA4でチャネル別やページ別の表を見ていて、各行を足した数がいちばん上の「合計」と合わず、どちらが正しいのか分からなくなることがあります。月次の報告で数字を求められると、なおさら困ります。この記事では、ずれる理由と、直すべきずれかどうかの見分け方を順に整理します。

結論：GA4の「合計」は、行を足した数ではなく、全体を数え直した数です。ユーザー数やセッション数は1人が複数の行に出るため、行の合計が合計値より多くなるのは仕様どおりです。行の合計が少ないときは、(other)の行、データのしきい値、(not set)の行で表示から外れた分があります。まず「指標は足せる種類か」「多いか少ないか」の2点を確かめると、直すべきずれかどうかがすぐに分かります。

まず知る：GA4の「合計」は行を足した数ではない

GA4のレポートの表では、いちばん上に「合計」の行があり、その下にチャネル・ページ・日付などの行が並びます。この「合計」は、下の行を足し算した数ではありません。同じ条件でもう一度、全体を数え直した数です。そのため、指標によっては行を足しても合計と一致しないのが正常な動きです。

指標は、大きく2つに分けて考えると分かりやすくなります。

指標の種類例行を足すと合計になるか
件数を数える指標イベント数、表示回数、キーイベント（コンバージョン）の数、収益原則なる（しきい値や(other)の影響がなければ）
重複しない人・訪問を数える指標ユーザー数（アクティブ ユーザー数）、総ユーザー数、新規ユーザー数、セッション数ならないことが多い

たとえば、同じ人が今週「自然検索」と「広告」の両方から来た場合、チャネル別の表ではその人が2つの行に1人ずつ数えられます。しかし合計の行では、その人は1人です。1人が複数の行に出るほど、行の合計は合計値より大きくなります。日付を行にした表で、毎日のユーザー数を足すと期間全体のユーザー数より大きくなるのも同じ理由です。

なお、GA4の画面で単に「ユーザー」と表示される数は、通常「アクティブ ユーザー数」を指します。「総ユーザー数」とは別の指標なので、比べる指標の名前がそろっているかも確かめてください。（出典：Google アナリティクスの UI と BigQuery エクスポートのギャップを埋める｜Google for Developers）ユーザー関連の指標の定義は、Googleのヘルプにまとまっています。（出典：[GA4] Understand user metrics｜Analytics Help）

ポイント：「合わない」と感じたら、最初に見ている指標が足し算できる種類かどうかを確かめてください。ユーザー数やセッション数で行の合計が合計値を上回っているだけなら、多くは仕様どおりで、直すものはありません。

行の合計と合計値が合わない原因6つ

当社が計測の点検で確認することが多い原因は、次の6つです。1つだけでなく、いくつかが重なっていることもあります。

原因起きていることずれ方
1. 重複しない数の指標を足しているユーザー数・セッション数などは、1人・1回が複数の行に出る。行を足すと重複して数えられる行の合計が多い
2. 近似で数えているGA4はユーザー数・セッション数などを、HyperLogLog++という方法で推定している。行ごとと全体とで、小さな誤差が出るどちらにも小さくずれる
3. (other)行・行数の上限表の行数が上限を超えると、数の少ない値が「(other)」にまとめられる。フィルタで(other)を隠していると、その分が行から消える行の合計が少ない
4. データのしきい値ユーザー属性などを含むレポートで、人数の少ない行が表示から外される行の合計が少ない
5. サンプリングデータ探索などで扱うデータが多いと、一部のデータから全体を推定するどちらにもずれる
6. 行の条件で数える対象が変わるディメンションを追加すると、その値を持たないイベントが計算から外れることがある。「(not set)」の行の扱いでも変わる行の合計が少ないことが多い

原因2について、Googleの開発者向けブログでは、ユーザー数やセッション数などの数はHyperLogLog++で推定しており、画面やAPIの値は一定の精度の近似値になると説明されています。例として、セッション数は95%の信頼区間で±1.63%程度とされています。（出典：Google アナリティクスの UI と BigQuery エクスポートのギャップを埋める｜Google for Developers）

原因3について、Googleのヘルプでは、表の行数が上限を超えると、多い値だけを表示し、残りを「(other)」の行にまとめると説明されています。1つのディメンションの値が500を超えると「高基数」とされ、副次ディメンションやフィルタ、比較を使うと(other)が出やすくなります。（出典：About the (other) row｜Analytics Help）

原因4について、データのしきい値はシステムが決めるもので、利用者は調整できません。ユーザー属性のデータなどを含む場合に、一部のデータが除外されることがあります。（出典：[GA4] データのしきい値について｜アナリティクス ヘルプ）

原因5・6について、サンプリングはレポートやデータ探索で起こりうること、またレポートにディメンションを加えると計算に使うイベントが少なくなることがあると、Googleの公式資料に書かれています。（出典：レポート表示内容の比較｜アナリティクス ヘルプ／レポートデータの期待値｜Google for Developers）

「多い」か「少ない」かで原因を絞る

原因は、行の合計が合計値より多いか少ないかで、かなり絞れます。

行の合計が多い

重複して数えている可能性が高い

  • 見ている指標がユーザー数・セッション数・新規ユーザー数か
  • 行のディメンションが、1人が複数の値を持てるもの（チャネル・ページ・日付・端末など）か
  • ほとんどの場合は原因1で、仕様どおり

行の合計が少ない

表示から外れている行がある可能性が高い

  • 表の中に「(other)」や「(not set)」の行があるか、フィルタで隠していないか
  • データ品質のアイコン（しきい値・サンプリング）が出ていないか
  • イベント数・キーイベント数のような件数の指標で少ないなら、原因3・4・6を優先して疑う

差が1〜2%程度で、指標がユーザー数やセッション数なら、原因2（近似）の範囲であることが多いです。一方、イベント数・キーイベント数・収益のような件数の指標で、行の合計が合計値より大きく少ない場合は、仕様だけでは説明しにくいので、次の手順で確かめてください。

どの原因かを見分ける確認手順

次の順に進めると、多くの場合10〜20分で当たりがつきます。期間と指標は、比べたい表とそろえてください。

確認の順番

  • 手順1：指標の名前を確かめる。「ユーザー」「総ユーザー数」「新規ユーザー数」「セッション」なら、まず原因1を前提に考える
  • 手順2：同じ表で、指標を「イベント数」に切り替えて行の合計と合計値を比べる。イベント数なら一致するのに、ユーザー数だけ合わないなら原因1・2でほぼ確定
  • 手順3：表の右上付近にあるデータ品質のアイコンを確かめる。しきい値やサンプリングの表示があれば原因4・5
  • 手順4：表を最後のページまで送り、「(other)」「(not set)」の行がないかを見る。フィルタや検索窓で行を絞っていないかも確かめる（原因3・6）
  • 手順5：副次ディメンションや比較を外して、同じ数字を見直す。外すと合うなら、行の条件で数える対象が変わっている（原因3・6）
  • 手順6：期間を広げる、またはユーザー属性のディメンションを外して見直す。しきい値は期間を広げると除外が減ることがある（原因4）
  • 手順7：データ探索で合わない場合は、同じ内容を標準レポートでも見る。標準レポートは集計済みのデータを使うため、(other)やサンプリングが出にくい（原因3・5）

注意：Looker Studioやスプレッドシートに書き出した表で、日別やチャネル別のユーザー数を「合計」の関数で足すと、原因1の重複がそのまま数字に入ります。ユーザー数の合計が欲しいときは、足し算ではなく、合計の行（または期間全体を数え直した値）を使ってください。

原因別の対処と、ずれないレポートの作り方

原因1・2：重複・近似

足さずに、合計の値を使う

  • ユーザー数・セッション数は、行の足し算で合計を出さない
  • チャネル別の内訳は「構成比のめやす」として見る
  • 月次の報告では、合計の値とその定義を一緒に書く

原因3：(other)

行の数を減らす

  • 副次ディメンションや比較を外し、必要な軸だけにする
  • 期間を短くして分けて見る
  • ページのURLのパラメータで値が増えすぎていないかを点検する

原因4・5：しきい値・サンプリング

条件を軽くする

  • ユーザー属性のディメンションを外す、期間を広げる
  • データ探索ではなく標準レポートで確認する
  • 正確な数がどうしても必要なら、BigQueryへの書き出しを検討する

原因6：数える対象

ディメンションの付き方を点検する

  • 「(not set)」が多いディメンションは、イベントへの値の付け方を見直す
  • カスタムディメンションは、送っていないイベントがあることを前提に見る
  • 比べる2つの表で、ディメンションと絞り込み条件をそろえる

Googleの資料では、BigQueryに書き出したデータからは近似ではない正確な数を計算でき、(other)へのまとめやサンプリングも起きないと整理されています。ただし、しきい値やGoogleシグナルによる重複除去など、画面のレポートにしかない処理もあるため、BigQueryとも完全には一致しません。（出典：Google アナリティクスの UI と BigQuery エクスポートのギャップを埋める｜Google for Developers）書き出すかどうかの判断は、GA4のデータ保持期間は初期設定のままでいい？14か月への変更とBigQuery連携の判断基準で整理しています。

レポートを毎月作っている場合は、「ユーザー数は合計の値を使い、チャネル別の内訳は足し算しない」といった数字の扱いのルールを報告書の欄外に1行書いておくと、社内で「合計が合わない」と問い合わせが来るのを防げます。レポートの自動化の設計は、Looker Studioでレポート自動化｜設計6ステップも参考にしてください。

どこまでの差なら気にしなくてよいか

行の合計と合計値の差が何%なら正常という公式の基準はありません。そのうえで、当社が実務で見ている目安は次のとおりです。

  • ユーザー数・セッション数で、行の合計が多い：原因1の重複が中心で、多くは気にしなくてよい状態です。チャネルや日付の行が多いほど差は大きくなります
  • ユーザー数・セッション数で、差が1〜2%程度：近似による誤差の範囲であることが多く、直すものはありません
  • イベント数・キーイベント数・収益で、行の合計が数%以上少ない：(other)・しきい値・(not set)のどれかが効いています。手順3〜6で原因を確かめてください
  • 前月までは合っていたのに、急に大きくずれた：タグやイベント設定の変更、URLの変更による行の増加を疑い、計測の設定から点検してください

合計値そのものが広告の管理画面やECの売上と合わない場合は、別の問題です。広告やセッションとのずれはGA4のセッション数・ユーザー数が合わない理由、売上とのずれはGA4の収益がECの売上と合わない原因と確認手順で解説しています。

LnXの見解

「GA4の合計が合わない」という相談の多くは、計測の不具合ではなく、ユーザー数を足し算してしまっていることが原因です。数字が間違っていると思い込んでタグを触ると、かえって本当の不具合を作ってしまうことがあります。まずは指標の種類と、多いか少ないかを確かめるだけで、直すべきかどうかの大半は判断できます。

一方で、件数の指標で行が少なく出ている場合は、(other)や(not set)の裏に、イベントの設計やURLの整理の問題が隠れていることがあります。広告の成果をチャネル別に見る表でこれが起きていると、予算の判断を誤る原因になります。

LnXの広告運用代行では、広告の運用に加えて、GA4やコンバージョン計測などの計測環境の構築まで自社で対応しています。広告の成果を正しく比べられる数字の土台から整えたい場合は、ご相談ください。

※GA4の画面・指標の名前・仕様は更新されます。設定を変える前に、最新の公式ヘルプもご確認ください。

よくある質問

QGA4のユーザー数は、行の合計と合計値のどちらが正しいですか？

期間全体の人数としては、合計の値を使ってください。ユーザー数は1人が複数の行に出るため、行を足すと同じ人を重ねて数えてしまいます。行の値は、チャネルやページごとの内訳のめやすとして見るのが安全です。

Q日別のユーザー数を足すと、月のユーザー数より多くなります。おかしいですか？

おかしくありません。同じ人が月に何日も来ると、日別の表では毎日1人ずつ数えられますが、月の合計では1人です。月のユーザー数が必要なときは、期間を1か月にして合計の値を見てください。

Qイベント数でも行の合計が合計値と合いません。なぜですか？

イベント数は本来足し算できる指標なので、表示から外れている行がある可能性が高いです。表の中の(other)や(not set)の行、フィルタによる絞り込み、データ品質のアイコン（しきい値・サンプリング）を確かめてください。

Q(other)の行をなくすにはどうすればよいですか？

副次ディメンションや比較を外す、期間を短くして分けて見る、標準レポートで確認するなど、表の行数を減らす方法が基本です。ページのURLにパラメータが付いて値が増えすぎている場合は、URLの整理も検討してください。

QLooker Studioで作ったレポートの合計も合いません。

Looker Studioでも、表の集計行や、書き出したデータを足し算した値は、GA4の合計の値と一致しないことがあります。ユーザー数のように重複しない数の指標では、内訳の行を足すと重複が入るためです。期間全体のユーザー数は、内訳なしのスコアカードなどで表示し、GA4の合計の値と並べて確かめてください。
